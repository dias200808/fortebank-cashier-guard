# Разбор датасета (open/)

Источник: просмотр кадров каждые 2 с и ±4 с вокруг размеченных таймкодов (шаг 0.5 с). Типы нарушений — **наши гипотезы**: в разметке есть только метка и таймкод.

## Данные

- 42 файла `.mov`, h264, 464×848 (портрет), ~30 fps, без звука, 11.6–142.5 с (медиана 22.7 с, всего ~24 мин).
- Разметка `open_labels.xlsx`: 22 с нарушением (по одному таймкоду), 20 без нарушения.
- Имена: `X-1`, `X-2` — латиница, остальные `Х-…` — кириллица. Нормализовать перед join.
- **Дубликаты:** `Х-4` ≡ `Х-47`, `Х-5` ≡ `Х-48` (побайтно). `Х-4` размечен на 57 с, `Х-47` на 68 с → в одном видео два нарушения. При train/val сплите дедуплицировать.
- Минимум 3 ракурса/планировки, 3 кассира, мебель переставляется (машинка слева/справа, сейф справа/сзади). Стеклянная перегородка отражает людей снаружи → детектор людей даст ложные срабатывания без маски/трекинга.
- Нижние ~35% кадра — белый стол на переднем плане (мёртвая зона).

## Что считается нормой (по чистым видео)

- Открыть сейф при клиенте — **нормально**; важно закрыть.
- Корректный уход: сейф заперт, ключ унесён, ноутбук закрыт/заблокирован, на столе нет наличных (Х-12, Х-25, Х-27, Х-29, Х-23).
- Обслуживание клиента: удостоверение → наличные → пересчёт (руками + машинка) → сейф → клиент уходит (Х-3, Х-5, Х-19, Х-35, Х-39).
- Инкассатор передаёт сумку на столе (Х-16); кассир вскрывает сумку и пересчитывает (Х-14).

## Выводы для решения

- Каркас: трекинг людей (кассир / клиент / инкассатор / посторонний; вход и выход через дверь) + состояния объектов (сейф, дверь, экран, наличные, сумка, чашка, сумка/одежда) + rule engine «событие → тип → пункт норматива».
- Детекция объектов — на каждом видео заново, без хардкода зон (тест снимут с нового ракурса).
- Против ложных срабатываний: в чистых видео тоже уходят, открывают сейф и встают — решает **состояние** в момент события, а не само событие.
- Из коробки (COCO): person, cup, bottle, handbag, backpack, laptop, cell phone, book. Дообучить или взять open-vocab: банкноты, инкассаторская сумка, дверца сейфа, дверь, удостоверение, ключ.
- Лицензии: ultralytics — AGPL-3.0; по FAQ #24 нужна лицензия, разрешающая коммерческое использование. Перед финалом сверить лицензии всех моделей и весов.
- Мелкие процедурные типы (11, 13–15) на разрешении 464×848 ненадёжны — кандидаты в «низкий приоритет».
